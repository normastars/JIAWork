# 嘉迪查数数据模型配置说明

本文面向维护查数口径的人员。员工在“嘉迪专家”的普通对话中提问；维护人员在 **设置 → 数据模型** 决定哪些 SQL Server 表、字段和指标可供专家查询。这里配置的是**业务数据模型**，不是大模型服务的地址或 Key；后者在 **设置 → API 配置** 中设置。

| 设置项 | 配什么 | 用途 |
| --- | --- | --- |
| API 配置 | JIAWork-Admin 的 API 地址、平台 Key 和允许使用的模型 | 让嘉迪专家理解问题并调用工具。上游服务商 Key 配在管理平台，不填入 App。 |
| 数据模型 | SQL Server 表、维度、关联、指标和口径 | 限定专家可以查哪些业务数据，以及如何统计。 |

API 配置的操作见 [README 的管理平台连接说明](../README.md#连接-jiawork-admin-模型平台)；下文只介绍数据模型。

## 开始前

- App 已能连接查数用的 SQL Server 数据库，数据库账号具有所需表或视图的读取权限。“刷新表结构”应能列出数据库表。数据库连接由部署人员准备，当前页面不填写数据库密码。
- 已在“API 配置”中设置可用的模型地址和平台 Key，否则嘉迪专家无法理解问题并调用查数工具。
- 本机演示可先在仓库根目录运行 `node scripts/nlq-demo-db.cjs` 准备模拟库；完整的启动与验证问题见[自然语言查数 Demo](自然语言查数-Demo.md)。真实 CAC ERP 数据应先同步到影子库，再让查数服务读取影子库。

## 配置步骤

1. **数据表**：点击“刷新表结构”，从数据库表或视图中添加允许查询的对象。用于统计的基础表必须选择日期字段；只提供名称、区域等属性的关联表可以不选日期字段。展开一张表，把客户、供应商等业务维度映射到实际字段。
2. **业务维度**：添加需要筛选或分组的名称，例如“客户”“区域”。别名用于帮助专家理解用户的不同说法。添加维度后，回到“数据表”把它映射到相应表的字段；仅添加名称不会自动找到数据库字段。
3. **表关联**：如果维度在另一张表上，选择来源表及关联字段、目标表及关联字段，并指定关系类型。来源通常是订单等统计基础表，目标通常是客户等资料表。**多对一**和**一对一**可参与汇总；**一对多**仅记录关系，不参与汇总，避免重复计数。发布时，多对一会检查目标关联字段是否重复；一对一还会检查来源关联字段。
4. **统计指标**：选择基础表、数值字段、统计方式和单位，写清业务口径。可选“扣减字段”，例如“下单数量－已收数量”。“期间累计”对所选月份内的记录求和；“最近快照”取期间内最近一次快照，不把不同日期的库存快照相加。
5. **验证与发布**：先保存草稿，再选择指标和月份点击“预览查询”。页面显示结果、执行的参数化 SQL 和绑定参数，可点击“复制 SQL 与参数”。有待发布修改且预览成功后，点击“发布模型”。发布会再次核对实际表、字段、数据类型和关联字段唯一性；成功后版本号增加，嘉迪专家的新查询立即使用已发布模型。

预览只按选定的**指标和月份**查询草稿模型，没有客户等筛选条件。因此预览总数可能不同于嘉迪专家按客户筛选后的回答。修改指标或月份后需要重新预览。复制内容包含 SQL 文本和绑定参数说明；它不是把参数值直接拼进 SQL 的可执行脚本。

## 示例：为销售订单增加“区域”维度

演示库已有 `dbo.SalesOrderLine`，另有 `dbo.CustomerMaster`，其中 `customer_name` 对应客户、`region_name` 对应区域。操作顺序如下：

1. 在“数据表”添加 `dbo.CustomerMaster`，不选日期字段。
2. 在“业务维度”添加“区域”，回到 `dbo.CustomerMaster` 将该维度映射到 `region_name`。
3. 在“表关联”添加关系：来源 `dbo.SalesOrderLine.customer_name` → 目标 `dbo.CustomerMaster.customer_name`，类型选“多对一”。新增关系时请核对来源和目标，页面的初始选择不一定是这两张表。
4. 保存草稿；在“验证与发布”预览“销售订单数量”、`2026-10`，演示库总数应为 **230 件**；确认无误后发布。
5. 在“嘉迪专家”输入“2026 年 10 月按区域看看销售订单数量”。演示数据对应华东 **180 件**、华南 **50 件**。

## 保存位置与当前边界

- 草稿和已发布模型分别保存在 App 用户数据目录的 `nlq-model-draft.json`、`nlq-model.json`；它们只包含表、字段、关系与指标定义，不包含数据库密码。发布不会改写 SQL Server 中的业务数据。
- 数据库连接由部署人员通过环境变量或用户数据目录的 `nlq-connection.json` 提供。该文件可能包含数据库密码，**不要提交到仓库或发送给员工**。演示脚本会为本机模拟库写入连接配置；更换电脑或数据库需重新配置并启动 App。
- 当前模型和连接配置按**本机**保存，不会自动同步到其他员工电脑；Demo 也没有按角色限制谁可以查看或修改数据模型。正式接入嘉迪影子库前，需要明确统一的模型发布位置、权限和业务口径。
- 当前仅支持从统计基础表到关联表的一层安全关联。需要复杂计算或多层关联时，先在影子库提供经过业务确认的只读视图，再把该视图加入数据模型。查数工具只接受已配置的指标和维度，不提供任意 SQL 入口。

## 常见问题

| 现象 | 检查项 |
| --- | --- |
| “刷新表结构”失败 | 检查 App 所在机器到 SQL Server 的网络、数据库连接配置和只读账号。 |
| 发布提示表或字段不存在 | 核对所选表、日期字段、维度映射、指标字段和关联字段是否仍在数据库中。 |
| 发布提示关联字段重复 | 多对一关系的目标字段应唯一；先核对资料表数据或调整关系。 |
| 预览成功但专家查不到新维度 | 确认已点击“发布模型”，并在新问题中明确指标、月份及要分组的维度。 |

现有默认指标和模拟数据口径可参考 [`src/main/nlq/model.json`](../src/main/nlq/model.json)；实际规则以应用中的已发布模型为准。
