# 嘉迪查数数据模型配置

数据模型现在由 **JIAWork-Admin** 统一管理。员工仍在 JIAWork App 的“嘉迪专家”对话中提问；App 用平台签发的 API Key 读取已发布模型，再用本机配置的只读 SQL Server 账号查询影子库。数据库密码不上传到 Admin。

## 准备

1. 启动 JIAWork-Admin，配置模型渠道并签发平台 API Key。
2. 在 App 的“设置 → API 配置”填写管理平台的 `/v1` 地址和平台 Key。
3. 由部署人员配置 App 到 SQL Server 影子库的只读连接。App 启动后会将可用表和字段名称上报给 Admin，供编辑时选择；在 Admin 的“数据模型”点击“刷新表结构”即可看到。

同一管理平台下的 App 应连接同一套影子库结构；管理页显示最近一次上报的表结构。

本机使用 CAC 导出数据时，按[CAC 数据导入与查数](CAC数据导入与查数.md)建立影子库。正式接入时应把 CAC 数据持续同步到影子库，不让 App 查询 ERP 原库。

## 在 Admin 配置

打开管理页的“数据模型”：

1. **数据表**：选择允许查询的表或视图，填写日期字段。基础统计表必须有日期字段；客户等资料表可以留空。把业务维度映射到实际字段。
2. **业务维度**：填写“客户”“供应商”等名称和常见别名，用于筛选、分组和理解口语提问。
3. **表关联**：选择来源表、目标表和关联字段。多对一或一对一可用于汇总；一对多只记录关系，不参与汇总，以免重复计数。
4. **统计指标**：选择基础表、数值字段、可选扣减字段、期间累计或最近快照、单位和口径说明。数量涉及不同计量单位时，填写必填筛选维度（如 `item_code`），禁止跨物料混加。
5. 点击“保存草稿”，确认后点击“发布到 App”。App 在下一次查数前拉取新版本，并验证实际表、字段、数据类型及关联键。验证失败时会拒绝使用新模型，并在 App“设置 → 数据模型”显示原因。

Admin 不直接连接 SQL Server，因此管理页不能预览查询结果。配置完成后，在 App 的“嘉迪专家”中提问验证业务口径。管理页只保存模型结构和 App 上报的表结构，不保存 SQL Server 连接密码。

## 迁移旧的本地模型

如果此前在 App 中改过模型，先把 App 用户数据目录中的 `nlq-model.json` 内容复制到 Admin“数据模型 → 导入 / 导出”，点击“导入上方 JSON”“保存草稿”“发布到 App”。macOS 的文件通常在 `~/Library/Application Support/LobsterAI/nlq-model.json`；Windows 在 `%APPDATA%/LobsterAI/nlq-model.json`。

新版本 App 首次用 Admin 模型替换旧本地模型时，会保留 `nlq-model.pre-admin.json` 备份。旧的 `nlq-model-draft.json` 不会被自动发布；如果草稿才是要迁移的版本，可以导入该文件，但应先检查其内容。

## 当前范围

查数工具只接受已发布模型中的指标、维度和筛选条件，不接受用户提交任意 SQL。复杂计算可先在影子库建立只读视图，再将视图加入模型。当前 CAC 模型不包含报价记录、库存结存和采购未收指标；销售金额在这批导出中全为 0，因此也未开放。生产物料和 BOM 的日期来自相关生产单的最早 `DATE_FINSH`，实际业务含义仍需嘉迪确认。当前阶段暂不按员工角色隔离可查指标或数据行。
