# 自然语言查数 Demo

本 Demo 按《自然语言查数－方案与实施手册》的思路，在 JIAWork App 内实现受控指标查询。模型把问题转成结构化请求；Electron 主进程根据语义模型生成 SQL Server 查询并计算结果。当前仅使用模拟数据，没有连接 CAC ERP。

## 用户怎么用

打开已安装的 JIAWork App，直接在“嘉迪专家”的普通对话中提问，例如“帮我看看 2026 年 10 月客户甲的销售订单一共多少件，比去年 10 月多多少”。专家会按需调用受控查数工具，返回 180 件、同比多 30 件，并说明统计口径。

用户无需启动 Docker、运行命令或填写数据库账号。模型 API 配置仍按工作台现有方式预先完成。查询库未连接时，助手会显示工具错误，不能编造数字。

## 新增表和业务场景

在 App 中打开“设置 → 数据模型”：

具体字段填写和“客户区域”关联示例见[数据模型配置说明](数据模型配置说明.md)。

1. 刷新表结构，选择影子库中允许查询的表或视图。为用于统计的基础表选择日期字段，并把客户、供应商等业务维度映射到实际字段。
2. 新增维度和表关联。关联从统计基础表指向名称表，多对一和一对一可用于分组、筛选；一对多只记录关系，不参与汇总，防止重复计算。
3. 新增指标，选择数值字段、可选的扣减字段、期间累计或最近快照、单位及口径说明。
4. 保存草稿，选择指标和月份预览结果及 SQL，再发布。发布时校验实际表和字段、指标数据类型及关联目标字段的唯一性。发布后“嘉迪专家”的普通对话立即使用新模型，无需重新打包 App。

草稿与已发布模型分别保存在 App 用户数据目录的 `nlq-model-draft.json`、`nlq-model.json`，只写入本机，不包含数据库密码。当前只支持基础表到关联表的一层安全关联；复杂的跨表计算可先在影子库建立只读视图，再将视图作为表加入模型。表关系与统计口径仍需业务人员核对；配置页面不会自动判断 ERP 业务含义。

## 部署人员一次性准备本机演示

需要 Node.js 24.15 及以上的 24.x 和 Docker。执行：

```bash
node scripts/nlq-demo-db.cjs
```

脚本启动独立的 SQL Server Developer Edition 容器，创建 `JIAWorkNLQDemo` 数据库、三张模拟业务表、一张客户资料表和只读账号，并将只读连接配置放入本机 App 的用户数据目录。容器仅绑定 `127.0.0.1:14333`，设置为 Docker 启动时自动恢复。本地密码保存在 Git 忽略的 `.work/` 和 App 用户数据目录，文件权限为仅当前用户可读；不要提交或发送。之后直接打开 App 即可。

开发时先退出已打包的 JIAWork，再执行 `npm run electron:dev`；开发版与已打包版共用单实例锁。无需再手动加载环境变量。

本机若为 Apple Silicon，SQL Server 容器会以 `linux/amd64` 模拟运行，速度可能较慢；[微软官方只支持 x86-64 容器主机](https://learn.microsoft.com/en-us/sql/linux/containers/deploy?view=sql-server-ver16)。

App 会使用现有“API 配置”中的模型地址和 Key。平台 Key 必须允许当前选中的模型；App 启动时会同步允许的模型范围。
如果在管理平台修改了这把 Key 的模型范围，请重启 App，让专家与默认模型重新同步。

## 验证问题

| 问题 | 模拟数据期望结果 |
| --- | --- |
| 2026 年 10 月客户甲的销售订单数量是多少？同比如何？ | 180 件；上年同期 150 件；同比增长 20% |
| 2026 年 10 月各供应商的采购未收数量是多少？ | 供应商甲 150 件、供应商乙 0 件 |
| 2026 年 10 月末各仓库的库存数量是多少？ | 原料仓 160 件、成品仓 70 件 |

嘉迪专家在对话里说明查询结果、期间和口径；“设置 → 数据模型”可预览查询结果及 SQL。查询工具只接受语义模型中的指标和维度；成员值通过参数绑定进入 SQL。数据库账号只有读取权限。

运行数据库集成测试：

```bash
set -a
source .work/nlq-demo-app.env
set +a
npm test -- nlq
```

## 当前边界

这是本机 SQL Server 演示：App 主进程直接使用本机只读账号访问模拟库。它没有把数据库连接信息打包进安装包；换一台电脑时，需要部署人员先提供可访问的查询服务或连接配置。Demo 暂不区分员工身份与角色，所有使用者可查询同一批模拟指标。接入真实 CAC 数据前，需要建设影子库和集中查询服务、替换语义模型、核对业务口径，并按实施手册补齐身份、指标和行级权限、评测集及审计要求。

停止测试容器：`docker stop jiawork-nlq-sqlserver-demo`。再次运行 `node scripts/nlq-demo-db.cjs` 可重新启动并确认模拟表已建立。
